# CHROTE Test Coverage

## Current Gates

Backend coverage is generated with the Go toolchain:

```bash
cd /path/to/chrote/src
go test -cover ./...
go test -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
```

Dashboard unit/component coverage is generated by Vitest with the V8 provider:

```bash
cd /path/to/chrote/dashboard
npm run test:unit -- --coverage
```

Vitest writes frontend coverage to `dashboard/coverage/`, including an HTML report and `coverage-summary.json`.

## Threshold Policy

Frontend coverage uses an explicit zero-baseline ratchet policy in `dashboard/vite.config.ts`: all thresholds are set to `0`, so CI always generates the report without pretending the current baseline is a meaningful quality floor. Raise those thresholds only with a bead that records the measured baseline and migration plan.

Backend coverage is measured in CI with:

```bash
cd /path/to/chrote/src
go test -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
```

No backend numeric threshold is enforced yet; the current policy is measured-and-tracked coverage.

## Playwright Coverage

`npm test` is a deterministic mocked Playwright gate. Live backend and terminal integration specs are excluded by default and run explicitly with:

```bash
cd /path/to/chrote/dashboard
CHROTE_TEST_URL=http://127.0.0.1:8095 npm run test:live
```

Live smokes are operator-run only unless CHROTE is deployed in a runner environment with access to the backend, tmux, and terminal proxy.
Point `CHROTE_TEST_URL` at the deployment actually under test; `8094` is only the compiled default of a from-scratch install, not evidence of where a running deployment listens.
